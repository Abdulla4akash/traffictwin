# VEC-08 instrumented reproduction verification

Status: implemented and accepted for one pinned protocol-seed weekend case.

VEC-08 compares a full VEC-07 execution to source-provided expected artifacts loaded directly from
the audited `tos-data` Git commit. It does not compare against values generated by TrafficTwin and
does not read the intentionally preserved older worktree versions as expected evidence.

## Reference case

The fixed case is `ukfleettrain-mappo_we_uk2030_fs0`:

- campaign `ukfleettrain_mappo`;
- weekend Manchester trace `trace_we_fullrsu.npz`;
- audited `ukfleettrain-MAPPO` 17-input actor;
- evaluator seed 0 and fleet seed 0;
- `uk2030` fleet, RSU capacity 2.5 per padded vehicle, and all 32,400 steps; and
- engine `v2_post_nrsus_fix`.

Expected values come from the exact pinned master CSV row, instrumented JSON, and enriched per-step
NPZ. All three Git-blob hashes are frozen in `vec_reproduction_contract.json`.

## Comparison policy

The verifier requires exact agreement for:

- expected master-row and instrumented-JSON scientific/provenance fields;
- JSON keys, dimensions, seeds, fleet, task/deadline outcomes, action shares, latency aggregate,
  fleet composition, and task counts;
- per-step keys, dtypes, shapes, arrivals, deadline successes, active counts, action counts,
  vehicle actions/arrivals/successes/queues/targets, fleet assignments, RSU backlog/state, and time;
- VEC-07 request identity, expected and observed hashes, and source/input immutability; and
- every scientific per-step and per-task array between the calibration and acceptance repeat.

The first full controlled CPU run was used only to freeze two narrow float32-reduction bounds before
the acceptance repeat:

| Field | Inclusive tolerance | Calibration observation |
|---|---:|---:|
| `run.avg_energy_j_per_task` | `max(1e-7, 3e-7 × abs(expected))` | `6.0301178e-8 J` |
| `per-step.lat_sum` | `max(0.00390625 ms, 3e-7 × abs(expected))` and at most 3 ULP | maximum `0.00390625 ms`, 3 ULP |

No task, action, deadline, queue, target, fleet, RSU, time, or count difference is covered by these
tolerances. Four ULPs and broader scalar drift are negative-tested. `wall_s` is excluded as
machine-dependent performance metadata. The runner's staged `actor.npz` basename is normalised only
after its exact actor ID and hash are verified from the receipt.

## Acceptance result

Two independent full JAX/JAXLIB 0.4.30 CPU runs completed through VEC-07. The acceptance report has:

- 61 exact checks;
- 2 checks within the frozen tolerance;
- 0 mismatches;
- 1 explicit wall-time exclusion; and
- 1 unavailable expected per-task comparison.

The two local runs were exactly identical for all JSON fields except `wall_s`, every per-step array,
and every per-task array. Against the pinned source artifacts, 9,536 of 32,400 per-step float32
latency sums differed within the declared three-ULP bound; all other per-step arrays were exact.
The final completion, per-class completion, actions, average latency, counts and fleet values were
exact. Average energy differed only by the admitted `6.0301178e-8 J` reduction rounding.

The portable report contains only source/observed hashes, aggregate values, comparison results,
runtime versions, and interpretation limits. It contains no actor, raw array, private path, host
name, or checkpoint content.

## Running the verifier

After producing two complete VEC-07 directories for the fixed case:

```bash
uv run python scripts/verify_vec_reproduction.py \
  --observed /path/to/acceptance/observed \
  --calibration /path/to/calibration/observed \
  --tos-data ../external/tos-data \
  --output docs/reference/generated/vec_reproduction_report.json
```

The script writes only an `exact` or `numerically_equivalent` report and refuses divergent output.
The report is [generated VEC-08 acceptance evidence](../reference/generated/vec_reproduction_report.json),
and the frozen method is the
[generated VEC-08 contract](../reference/generated/vec_reproduction_contract.json).

## Limits

This establishes numerical equivalence for one protocol-seed weekend case on the pinned CPU method.
It is not proof of cross-platform, GPU, every-scenario, or every-policy equivalence. The source
package has no expected per-task artifact for this case, so observed per-task output is VEC-07
schema-validated and repeat-exact but not compared with a source value. VEC-08 does not create a
CLI/UI Run control; product direct launch stays false until the VEC-10 interface and capability
gates are implemented.
