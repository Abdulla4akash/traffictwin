# Provenance Graph Exports And Explorer

TrafficTwin `PRO-02` projects an existing `ProvenanceTrace` into a deterministic bounded graph and
exports it as Graphviz DOT or GraphML. The graph records software lineage. It does not establish
that a row, vehicle, RSU, incident, configuration, or policy caused an observed outcome.

## What It Can Show

Depending on the selected run, metric, or diagnostic root, a graph can connect:

```text
result -> definition -> canonical table -> canonical record -> source row -> source file
       -> validation finding
       -> run -> seed / experiment / environment / checkpoint / fingerprint
```

The graph uses the same nodes and typed relations as JSON and Markdown provenance. Export does not
recompute metrics or diagnostics and does not inspect source files.

## Bounded Selection

Every graph has explicit node and edge limits:

- default: 120 nodes and 240 edges;
- maximum: 500 nodes and 2,000 edges;
- the root is always retained;
- selection is root-centred deterministic breadth-first traversal over both incoming and outgoing
  neighbourhoods;
- retained edges keep their original direction;
- exact total, retained, omitted, and `truncated` values are published.

The graph ID describes the complete sanitised graph and therefore does not change when only the
view limits change. The `ProvenanceGraphView` fingerprint describes the exact bounded view and does
change with limits or disclosure profile.

## Disclosure Profiles

`safe` is the default. It recursively redacts local POSIX, Windows, home-relative, and `file://`
paths while retaining typed descriptions, node attributes, and bundle-relative source references.

`structure_only` removes descriptions, attributes, and source references. It retains graph shape,
typed nodes, statuses, labels, synthetic flags, relations, and confidence.

Neither profile is a complete anonymisation tool. Run IDs, vehicle IDs, RSU IDs, bundle-relative
filenames, or other domain labels can still identify private material. Review graph exports before
sharing them outside the authorised research context.

## CLI

Inspect the public method contract:

```bash
traffictwin provenance graph-contract --format text
traffictwin provenance graph-contract --format json
```

Export a bounded metric graph as DOT:

```bash
traffictwin provenance export tests/fixtures/bundles/baseline_valid \
  --root-type metric \
  --root-id task.completion.rate \
  --format dot \
  --max-nodes 80 \
  --max-edges 160 \
  --output completion-provenance.dot
```

Export a structure-only diagnostic graph as GraphML:

```bash
traffictwin provenance export tests/fixtures/bundles/variation_valid \
  --root-type rule \
  --root-id R2 \
  --format graphml \
  --redaction structure_only \
  --max-nodes 120 \
  --max-edges 240 \
  --output R2-provenance.graphml
```

The ordinary trace commands also accept `--format dot` or `--format graphml` with contract defaults:

```bash
traffictwin provenance metric tests/fixtures/bundles/baseline_valid \
  task.completion.rate --format dot
```

## Streamlit

1. Select an accepted bundle.
2. Open **Provenance Explorer**.
3. Choose a metric, diagnostic rule, or run root.
4. Open the **Graph** tab.
5. Select node/edge limits and `Safe` or `Structure Only` disclosure.
6. Inspect retained/total counts, omissions, the rendered graph, and a selected node.
7. Download the exact bounded DOT or GraphML from **Export**.

The UI uses the same typed view and DOT serializer as the CLI. Graph layout is generated by the
viewer and is not part of the deterministic research artifact.

## Python

```python
from traffictwin.provenance.graph_export import (
    GraphRedactionMode,
    build_provenance_graph_view,
    provenance_graph_to_dot,
    provenance_graph_to_graphml,
)
from traffictwin.provenance.query import (
    build_provenance_context,
    get_metric_provenance,
)

context = build_provenance_context("tests/fixtures/bundles/baseline_valid")
trace = get_metric_provenance(context, "task.completion.rate")
view = build_provenance_graph_view(
    trace,
    node_limit=80,
    edge_limit=160,
    redaction_mode=GraphRedactionMode.SAFE,
)

dot = provenance_graph_to_dot(view)
graphml = provenance_graph_to_graphml(view)
```

## Stable Output Rules

- Existing safe trace node IDs are retained.
- Unsafe path-bearing node IDs receive deterministic aliases.
- Exported edges receive stable hash-based IDs.
- Trace and node timestamps are excluded.
- Node, edge, XML key, and DOT statement ordering is fixed.
- Invalid XML control characters are replaced.
- DOT strings and XML text are escaped by their respective serializers.
- Exporters never open node paths or follow links.

## Limitations

- Graph lineage is not causal attribution.
- A truncated graph is incomplete by design; use its omission counts before interpreting it.
- Safe mode still contains ordinary attributes and identifiers.
- Structure-only mode removes details and cannot answer value-level provenance questions.
- Graph layout varies by renderer and should not be compared as evidence.
- GraphML generation is standards-shaped and parser-tested; compatibility with every third-party
  graph product is not guaranteed.
- The current SUMO contract does not yet expose a graph-trace entry point. TOS aggregate traces can
  use the generic serializer, but their existing aggregate/canonical limitations remain visible.
