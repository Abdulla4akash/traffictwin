# Methodology diagram drafts

Three hand-drawn schematics for the dissertation's methodology chapter.

| File | Shows |
|---|---|
| `architecture_layers_draft.svg` | The layered architecture: ingestion → canonical → metrics/diagnostics/statistics → provenance → reporting → UI/CLI, with the boundary above which nothing computes |
| `manchester_data_flow_draft.svg` | The Manchester chain: raw sources → quarantine → accepted snapshots → matching/demand → evidence records |
| `experiment_instrument_draft.svg` | The experiment instrument: predeclaration → byte-bound approval → campaign cells → fresh admission → registry → STA-01 → results record, with the fail-closed points marked |

## These are illustrative drafts, not generated artifacts

Every one of these files was written by hand. **No generator produced them, no
script regenerates them, and no value in them was read out of a receipt, an
analysis payload, or the registry.** They are drawings of how the system is
meant to be understood — the shape of the argument, not evidence for it.

That distinction matters when reading them beside the rest of this directory.
The figures in `docs/dissertation_appendices/figures/` are rendered by
`scripts/generate_capacity_figures.py` from a completed campaign analysis
through the accepted REP-01 exporter, and the tables in
`docs/dissertation_appendices/tables/` by `scripts/generate_results_tables.py`
the same way. Both carry provenance notes naming the source payload and its
digest. These diagrams carry no such note because there is no source payload to
name: they are prose in picture form.

Each file is titled `DRAFT:` on its face so a diagram that escapes into a slide
deck still says what it is. **They have not been reviewed, and they are not
accepted documentation of the architecture.** Where a diagram and the code
disagree, the code is right and the diagram is out of date. Before submission
each one should be checked against the tree it claims to describe.

## Drawing conventions

- **Self-contained SVG.** Plain rectangles, lines, polygons and text. No
  external font file, stylesheet, script, image, or network reference of any
  kind; the only URL in each file is the SVG namespace itself.
- **Neutral greys, readable on either background.** Each diagram paints its own
  light-neutral panel (`#e6e8eb`) so it stays legible whether the page around it
  is light or dark. No fill is pure white or pure black — the darkest ink is
  `#1f2328` and the lightest fill `#e6e8eb`.
- **Dashed outlines mark boundaries and refusals**, not colour, so the meaning
  survives greyscale printing and colour-blind viewing alike.
- **Vertical flow, top to bottom**, consistent across all three so the three
  read as one family.
- Font is requested as `Helvetica,Arial,sans-serif`: a system-font stack ending
  in a generic family, so nothing is fetched and there is always a fallback.

## Redrawing them

Edit the SVG source directly. If a diagram is regenerated by a tool later, that
tool should write into a different directory with a provenance note, and this
one should be deleted rather than left to drift — a hand-drawn file sitting
beside generated output is exactly the confusion this note exists to prevent.
